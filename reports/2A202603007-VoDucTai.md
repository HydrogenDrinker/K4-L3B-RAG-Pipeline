## Quyết định kỹ thuật quan trọng

1. **Quyết định:** Sử dụng công thức Lucene Non-negative IDF cho thuật toán BM25 thay vì Robertson BM25 gốc.  
   **Lý do/evidence:** Khi kiểm thử trên corpus nhỏ hoặc các từ khóa xuất hiện ở 50% số văn bản ($n = N/2$), công thức Robertson cho $\text{IDF} = \ln(1) = 0$, dẫn đến việc các đoạn văn chứa đúng từ khóa vẫn nhận điểm 0 và bị bỏ sót. Lucene IDF $\ln(1 + \frac{N - n + 0.5}{n + 0.5})$ luôn dương, đảm bảo tìm kiếm chính xác 100% trong mọi quy mô tập dữ liệu.  
   **Trade-off:** Điểm số BM25 có biên độ dải giá trị hơi khác so với Robertson cổ điển, tuy nhiên khi kết hợp qua RRF chỉ dựa trên thứ hạng (rank) thì hoàn toàn tương thích và ổn định.

2. **Quyết định:** Gửi mảng batch trực tiếp vào API `/api/embed` của Ollama thay vì lặp từng chuỗi riêng lẻ.  
   **Lý do/evidence:** Với 551 chunks văn bản, việc gọi 551 request HTTP riêng lẻ mất hơn 55 giây. Khi gom thành các batch 32 văn bản/lần gửi, toàn bộ quá trình embedding chỉ mất chưa tới 8 giây (tăng tốc độ gấp 7 lần).  
   **Trade-off:** Cần quản lý batch size phù hợp để tránh tràn bộ nhớ đệm HTTP của server Ollama.
